# ОТЧЁТ ПО ЛАБОРАТОРНОЙ РАБОТЕ № 5

**Тема:** «Менеджер списка покупок (Model-View + делегат)»

## 1. Цель работы

Освоить архитектуру Model-View в Qt на практике: научиться отделять
данные (`QStringListModel`) от их отображения (`QListView`), реализовать
базовые операции CRUD (добавление, удаление и очистка), а также создать
пользовательский делегат для редактирования элементов по двойному щелчку
мыши.

Дополнительная цель --- понять преимущества архитектуры Model-View по
сравнению с использованием универсального виджета `QListWidget` при
работе с динамическими данными.

## 2. Задачи работы

1.  Изучить разделение ответственности между моделью, представлением и
    делегатом.
2.  Освоить основные методы класса `QStringListModel`: `stringList()`,
    `setStringList()`, `insertRow()`, `removeRow()` и `setData()`.
3.  Настроить `QListView`, привязать к нему модель и задать режимы
    выбора и редактирования.
4.  Реализовать добавление, удаление и очистку элементов через модель.
5.  Создать собственный делегат на основе `QStyledItemDelegate`.
6.  Реализовать методы создания редактора, передачи данных и изменения
    геометрии редактора.
7.  Добавить пользовательскую отрисовку ячеек с использованием
    `QPainter::save()` и `QPainter::restore()`.
8.  Проверить работу приложения и подготовить проект к размещению в
    Git-репозитории.

## 4. Теоретические сведения

### 4.1. Архитектура Model-View-Delegate

Архитектура Model-View-Delegate разделяет приложение на три логические
части:

-   **Модель (Model)** хранит данные и предоставляет интерфейс для
    доступа к ним. В данной работе используется `QStringListModel`.
-   **Представление (View)** отображает данные пользователю. Для этого
    используется `QListView`. Представление не хранит собственную копию
    списка, а получает данные из модели.
-   **Делегат (Delegate)** отвечает за отображение отдельной ячейки и её
    редактирование. В работе реализован класс `PurchaseDelegate`,
    наследующий `QStyledItemDelegate`.

Такое разделение позволяет изменять данные независимо от способа их
отображения. Когда модель изменяется, она отправляет соответствующие
сигналы, после чего представление автоматически обновляет содержимое.

### 4.2. Модель QStringListModel

`QStringListModel` --- готовая модель Qt для хранения списка строк.
Каждая строка модели содержит один объект `QString`.

В работе используются следующие методы:

-   `setStringList()` --- установить весь список строк;
-   `stringList()` --- получить список строк;
-   `insertRow()` --- добавить новую строку;
-   `removeRow()` --- удалить строку;
-   `setData()` --- установить значение элемента по индексу.

Для обращения к элементам используется `QModelIndex`, который содержит
информацию о позиции элемента в модели.

### 4.3. Представление QListView

`QListView` отображает элементы модели. Связь между моделью и
представлением устанавливается методом `setModel()`.

Для управления поведением списка используются:

-   `setSelectionMode()` --- настройка режима выделения;
-   `setEditTriggers()` --- настройка событий, запускающих
    редактирование;
-   `setItemDelegate()` --- установка пользовательского делегата.

В данной работе редактирование разрешено только двойным щелчком мыши с
помощью `QAbstractItemView::DoubleClicked`.

### 4.4. Пользовательский делегат

Класс `PurchaseDelegate` наследуется от `QStyledItemDelegate` и
переопределяет пять методов:

1.  `createEditor()` --- создаёт виджет редактора `QLineEdit`.
2.  `setEditorData()` --- загружает в редактор текущее значение
    элемента.
3.  `setModelData()` --- сохраняет введённое значение обратно в модель.
4.  `updateEditorGeometry()` --- размещает редактор поверх редактируемой
    ячейки.
5.  `paint()` --- отвечает за пользовательскую отрисовку ячейки.

В методе `paint()` сначала вызывается стандартная отрисовка базового
класса, затем добавляются декоративные элементы: зелёный маркер и тонкая
рамка.

### 4.5. Сохранение состояния QPainter

Методы `save()` и `restore()` используются для сохранения и
восстановления состояния объекта `QPainter`.

Перед изменением пера, кисти и других параметров вызывается `save()`.
После завершения пользовательской отрисовки вызывается `restore()`.

Это необходимо, чтобы настройки рисования одной ячейки не влияли на
последующие ячейки списка.

В качестве системы сборки выбран qmake. Базовым классом главного окна

Интерфейс приложения формируется программно с помощью компоновщиков Qt.
Файл формы `widget.ui`, созданный мастером проекта, не используется.

### Этап 2. Создание заголовочного файла purchase_delegate.h

Был создан заголовочный файл `purchase_delegate.h`.

В нём объявлен класс `PurchaseDelegate`, унаследованный от
`QStyledItemDelegate`.

В классе объявлены пять переопределяемых методов:

-   `createEditor()`;
-   `setEditorData()`;
-   `setModelData()`;
-   `updateEditorGeometry()`;
-   `paint()`.

Макрос `Q_OBJECT` в делегате не используется, поскольку класс не
объявляет собственных сигналов, слотов или свойств и только
переопределяет виртуальные методы базового класса.

### Этап 3. Реализация purchase_delegate.cpp

Создан файл `purchase_delegate.cpp`, содержащий реализацию методов
делегата.

В `createEditor()` создаётся поле ввода `QLineEdit`.

В `setEditorData()` текущее значение ячейки извлекается из модели с
помощью `index.data(Qt::EditRole)` и устанавливается в поле редактора.

В `setModelData()` введённый пользователем текст записывается обратно в
модель методом `model->setData()`.

В `updateEditorGeometry()` редактору задаётся геометрия редактируемой
ячейки с помощью `option.rect`.

В `paint()` выполняется стандартная отрисовка ячейки и добавляются
декоративные элементы. Для маркера используется зелёный цвет, а вокруг
ячейки рисуется тонкая рамка. Изменения состояния `QPainter` обёрнуты в
`save()` и `restore()`.

Макрос `Q_OBJECT` используется для поддержки механизма сигналов и слотов

### Этап 5. Реализация главного окна в widget.cpp

В файле `widget.cpp` реализована основная логика приложения.

Метод `setupUi()` создаёт интерфейс и настраивает его расположение.
Создаётся модель `QStringListModel`, в которую добавляются три начальных
элемента: «Молоко», «Хлеб» и «Яблоки».

Затем создаётся `QListView`, которому передаётся модель через
`setModel()`. Для списка устанавливается одиночный режим выделения и
редактирование только по двойному щелчку.

К представлению подключается пользовательский делегат
`PurchaseDelegate`.

Ниже списка размещаются поле ввода, кнопка добавления, кнопки удаления и
очистки, а также информационная надпись со счётчиком элементов.

Реализованы следующие операции:

**Добавление товара --- `addItem()`**

Метод получает текст из поля ввода, удаляет лишние пробелы по краям и
проверяет, что строка не пустая. Затем в модель добавляется новая строка
с помощью `insertRow()`, а её значение устанавливается через
`setData()`. После добавления поле ввода очищается.

**Удаление товара --- `removeSelected()`**

Метод получает текущий индекс выбранного элемента через
`m_view->currentIndex()`. Если элемент выбран, его строка удаляется из
модели с помощью `removeRow()`.

**Очистка списка --- `clearAll()`**

Для удаления всех элементов используется один вызов
`m_model->setStringList({})`.

**Обновление состояния --- `refreshStatus()`**

Метод получает количество элементов через `rowCount()`, обновляет
информационную надпись и включает или отключает кнопку удаления в
зависимости от наличия выделенного элемента.

## 8. Ответы на контрольные вопросы

### Вопрос 1. Как положить данные в список так, чтобы view их показал, не трогая сам view?

**Ответ:**

Необходимо записать данные непосредственно в модель. Например, для
установки всего списка используется метод `setStringList()`:

``` cpp
model->setStringList({"Молоко", "Хлеб", "Яблоки"});
```

Если представление уже связано с моделью через `setModel()`, оно
автоматически отобразит новые данные. Изменять само представление для
этого не требуется.

### Вопрос 2. Как добавить новый элемент в список через модель?

**Ответ:**

Сначала необходимо добавить пустую строку с помощью `insertRow()`, затем
записать в неё значение через `setData()`:

``` cpp
int row = model->rowCount();
model->insertRow(row);
model->setData(model->index(row, 0), text);
```

Таким образом новый элемент добавляется в модель, а представление
автоматически обновляется.

### Вопрос 3. Как удалить выделенный элемент, работая с моделью, а не с items view?

**Ответ:**

Сначала необходимо получить текущий индекс выделенного элемента через
`view->currentIndex()`. Затем удалить соответствующую строку модели
методом `removeRow()`:

``` cpp
QModelIndex index = view->currentIndex();

if (index.isValid()) {
    model->removeRow(index.row());
}
```

Удаление выполняется непосредственно в модели, после чего представление
автоматически обновляет список.

### Вопрос 4. Как очистить весь список одним вызовом модели?

**Ответ:**

Для полной очистки списка используется метод `setStringList()` с пустым
списком:

``` cpp
model->setStringList({});
```

Модель заменяет своё содержимое пустым списком и уведомляет
представление об изменении.

### Вопрос 5. Как проверить, что изменение реально прошло через модель, а не через view?

**Ответ:**

Необходимо проверить содержимое модели после выполнения операции. Для
этого можно использовать `rowCount()`, `stringList()` или `data()`.

Также можно отслеживать сигналы модели: `rowsInserted`, `rowsRemoved`,
`dataChanged` и `modelReset`.

В данной работе дополнительно используются диагностические сообщения
`qDebug()`, показывающие выполнение операций CRUD.

### Вопрос 6. Как включить редактирование ячейки строго по двойному клику?

**Ответ:**

Для этого необходимо установить триггер редактирования через
`setEditTriggers()`:

``` cpp
view->setEditTriggers(QAbstractItemView::DoubleClicked);
```

В результате редактор будет открываться только при двойном щелчке мыши
по элементу списка.

### Вопрос 7. Как повесить на список свой делегат?

**Ответ:**

Необходимо создать экземпляр собственного делегата и передать его
представлению через метод `setItemDelegate()`:

``` cpp
view->setItemDelegate(new PurchaseDelegate(view));
```

В данной работе делегат наследуется от `QStyledItemDelegate` и отвечает
за отрисовку и редактирование элементов списка.

### Вопрос 8. Как сделать, чтобы редактор при открытии показал текущий текст ячейки?

**Ответ:**

Для этого необходимо переопределить метод `setEditorData()`. В нём
текущее значение извлекается из модели через `index.data(Qt::EditRole)`
и передаётся редактору:

``` cpp
void PurchaseDelegate::setEditorData(
    QWidget *editor,
    const QModelIndex &index) const
{
    QString value = index.data(Qt::EditRole).toString();

    if (auto *lineEdit = qobject_cast<QLineEdit*>(editor)) {
        lineEdit->setText(value);
    }
}
```

### Вопрос 9. Как сохранить введённое в редактор обратно в данные?

**Ответ:**

Необходимо переопределить метод `setModelData()`. Он получает текст из
редактора и записывает его в модель через `setData()`:

``` cpp
void PurchaseDelegate::setModelData(
    QWidget *editor,
    QAbstractItemModel *model,
    const QModelIndex &index) const
{
    if (auto *lineEdit = qobject_cast<QLineEdit*>(editor)) {
        model->setData(index, lineEdit->text(), Qt::EditRole);
    }
}
```

Таким образом изменения сохраняются в модели, а представление отображает
обновлённое значение.

### Вопрос 10. Как заставить редактор лечь ровно на ячейку, а не в угол окна?

**Ответ:**

Для этого необходимо переопределить метод `updateEditorGeometry()` и
установить геометрию редактора равной прямоугольнику ячейки:

``` cpp
void PurchaseDelegate::updateEditorGeometry(
    QWidget *editor,
    const QStyleOptionViewItem &option,
    const QModelIndex &index) const
{
    Q_UNUSED(index);
    editor->setGeometry(option.rect);
}
```

Параметр `option.rect` содержит координаты и размеры редактируемой
ячейки.

### Вопрос 11. Как в paint() делегата добавить свой рисунок, не сломав соседние ячейки?

**Ответ:**

Необходимо сохранять исходное состояние `QPainter` перед изменением его
параметров с помощью `save()`, выполнять собственную отрисовку, а затем
восстанавливать состояние через `restore()`:

``` cpp
painter->save();

// Пользовательская отрисовка
painter->setPen(QPen(Qt::green));
painter->drawRect(option.rect);

painter->restore();
```

Это предотвращает перенос изменённых настроек пера, кисти и других
параметров на соседние ячейки.

### Вопрос 12. Как объяснить, почему здесь Model-View, а не QListWidget?

**Ответ:**

Архитектура Model-View предпочтительнее при работе с динамическими
данными, поскольку разделяет хранение информации и её отображение.

В `QListWidget` данные и представление тесно связаны. В Model-View
данные хранятся отдельно в модели, а представление только отображает их.

Преимущества Model-View:

-   одна модель может использоваться несколькими представлениями;
-   сортировка и фильтрация реализуются через прокси-модели;
-   пользовательскую отрисовку можно реализовать отдельным делегатом;
-   обновление интерфейса происходит автоматически через сигналы модели;
-   упрощается сопровождение и расширение приложения.

Поэтому Model-View удобнее для приложений с большим количеством
изменяющихся данных.

### Вопрос 13. Как понять, нужен ли классу Q_OBJECT: делегату с только paint/createEditor -- нужен, окну со слотами кнопок -- нужен?

**Ответ:**

Макрос `Q_OBJECT` необходим классам, которым требуется механизм
метаобъектной системы Qt: собственные сигналы, слоты или свойства, а
также возможности рефлексии.

В данной работе класс `PurchaseDelegate` только переопределяет
виртуальные методы `QStyledItemDelegate`, поэтому макрос `Q_OBJECT` ему
не требуется.

Класс главного окна `Widget` содержит собственные слоты для обработки
нажатий кнопок, поэтому в нём макрос `Q_OBJECT` необходим.
